# DB 선택: SQLite와 DuckDB 비교

같은 데이터(2025년 대여가능 수량 2,418만 8,026행), 같은 단계, 같은 PC에서 측정 (2026-10-17).

| 단계 | SQLite | DuckDB |
|---|---|---|
| 적재 (CSV 12개 → DB) | 151초 | 47초 |
| 정제·집계 (공백률 표, 점검 9개 항목) | 592초 | 7초 |
| DB 파일 크기 | 1,130MB | 77MB |
| 월별 공백률 쿼리 (전체 행 집계) | 222초 | 0.52초 |

- 두 DB 모두 서버 없는 파일 DB. 결과값 동일 확인 (측정 당시 정제 기준 "한 달 내내 0대인 달 제외"에서 월별 공백률, 출근 시간 대체 대여소 97곳 중 50곳).
- SQLite: 행 단위 저장. 한 건씩 넣고 꺼내는 서비스용 DB에 적합.
- DuckDB: 열 단위 저장·압축. 수천만 행 GROUP BY 집계에 적합 → 이번 프로젝트(분석 중심)에 선택.
- 적재 시간의 대부분은 CP949 CSV 읽기(pandas)로 두 DB 공통.
- 앱에는 원본이 아닌 집계 결과만 포함 (stations.json 약 340KB, empty_rate.json 약 400KB) → 앱 실행에 DB·서버 불필요.
